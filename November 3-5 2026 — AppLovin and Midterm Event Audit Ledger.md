## Evidence standard and definitions

- **Contemporaneous public GitHub commit:** Publicly viewable historical commit and timestamp. Shows what was recorded on GitHub then; it is evidence of a public *record*, not a broker trade fill.
- **Contemporaneous ChatGPT instruction:** User message in an earlier conversation, with its original conversation timestamp available for audit. The underlying transcript/export should be made available separately for independent verification; a description in this file is not itself an externally verified message.
- **Retrospective owner report:** Owner's later account of a previous decision or trade that was not independently timestamped at the claimed minute.
- **Hypothetical:** An expressly unexecuted counterfactual. Must never be included as an actually completed trade, a realized timing return, or a confirmed change to the ongoing virtual holdings.
- **Confirmed virtual decision:** An allocation action recorded as confirmed in this virtual research portfolio. It is *not* a verified real broker execution.
- **Publication time vs. event time:** A 22:16 GitHub correction can describe an earlier decision, but it was *published at 22:16*.

## C. Reconciling AppLovin without hindsight

**The defensible sequence is:**

1. APP was part of the initial recorded virtual sale on November 4 at 17:35.
2. By 17:37, the owner had issued a contemporaneous instruction to buy APP again ahead of earnings.
3. At 22:16, GitHub recorded APP as held but described it as though it had never been sold. The *end-of-evening holding state* and the *transaction chronology* are separate facts.
4. The owner later stated that APP was bought again shortly after 22:00 and before the 22:05 release. The exact time of that repurchase remains **unverified** from a contemporaneous execution record; the 17:37 instruction is evidence of earlier intent, not proof of exact fill.
5. The current research ledger should represent two APP events (virtual sale; reported virtual repurchase) rather than continuous holding. Reconstruct actual/virtual sale and rebuy prices before calculating trade-level gains or any benchmark-timing advantage.

**What this resolves:** The presence of "APP sold" in the original GitHub history and "APP held" in the 22:16 version are not irreconcilable states. They are consistent with a sale followed by a repurchase. The original 'held throughout' shorthand was incomplete and has been corrected in later notes. No original GitHub commit is deleted or backdated.

**What it does not resolve:** A GitHub note corrected at 22:16 does not independently verify a 22:00–22:05 trade, even when a prior message showed intent. The original ChatGPT message/transcript, if disclosed for review, strengthens chronological intent evidence. A contemporaneous order confirmation, transaction log, or independently timestamped communication would be needed to substantiate the precise execution claim.
